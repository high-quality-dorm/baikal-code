# Дизайн сайта Baikal

Дизайн-спецификация веб-интерфейса Baikal: дизайн-система (токены, цвета,
типографика), описание каждой страницы и её элементов, правила гостевого
доступа. Документ задаёт визуальный язык продукта; реализация — отдельный
этап.

Ключевые принципы:

- **Контент прежде всего.** Чат — центр продукта; навигация и служебные
  элементы не конкурируют с лентой сообщений.
- **Понятность доступа.** Неавторизованный пользователь сразу видит, что
  он гость, какие данные ему доступны и как войти.
- **Прозрачность ответа.** Каждый ответ можно раскрыть до SQL и служебных
  метаданных — продукт не скрывает механику.
- **Доступность.** Контраст текста ≥ 4.5:1, видимый фокус с клавиатуры,
  поддержка `prefers-reduced-motion`, адаптивность от 375px.

Правила:

- Контраст основного текста ≥ 4.5:1 в обеих темах; разделители и границы
  различимы в обеих темах (не только в светлой).
- Primary-кнопки и акцентные иконки используют семантические токены, а не
  сырые hex.
- Ошибки и предупреждения — только через destructive/аccent токены, цвет
  не единственный индикатор (добавляется иконка и/или текст).

### Типографика

Три семейства: UI-текст, дисплейные заголовки и моноширинный шрифт для SQL.
Все три поддерживают кириллицу.

| Роль            | Шрифт        | Веса       | Использование                          |
| --------------- | ------------ | ---------- | -------------------------------------- |
| UI / body       | Onest        | 300, 400, 500, 600 | Текст интерфейса, сообщения, формы |
| Display / headings | Unbounded | 400, 500, 600, 700 | Заголовки, hero, номер шага  |
| Mono / code     | JetBrains Mono | 400, 500   | SQL, метаданные, числа, код           |


### Форма, отступы, эффекты

- **Отступы:** 4/8px-ритм; вертикальная иерархия секций — 16 / 24 / 32 / 48px;
  горизонтальные внутренние поля адаптивны (16px на мобильном, 24px на
  десктопе).
- **Скругления:** 8px (элементы), 12px (карточки и сообщения), 16px
  (модальные окна, композер).
- **Тени:** плоские, минимальные — мягкая тень для карточек, всплывающих
  блоков и композера; без градиентов (кроме лёгкого брендового в hero
  лендинга).
- **Переходы:** 150–200ms, `ease`; hover — смена цвета/прозрачности без
  сдвига раскладки.
- **Иконки:** векторные (SVG), из одного набора (линейные, 1.5–2px),
  размеры — токены (16/20/24px). Декоративные иконки рядом с текстом —
  `aria-hidden="true"`; осмысленные иконки без текста — с текстовой
  альтернативой.
- **Фокус:** видимое кольцо `--color-ring` (2px) на всех интерактивных
  элементах, включая элементы внутри модалок.
- **Сокращённое движение:** `prefers-reduced-motion: reduce` отключает
  несущественную анимацию (стриминг-эффект печати, появление сообщений,
  параллакс), финальное состояние рендерится сразу.

### 3. Вход (`/login`)

Назначение: авторизация, чтобы получать ответы по своей роли.

1. **Компоновка.** Центрированная карточка на фоне приложения. Сверху —
   логотип и название, заголовок «Войти», подзаголовок «Получайте ответы
   по своей роли — студент, преподаватель или администрация».
2. **Поля формы.** Email (label «Email», `type="email"`, валидация на
   клиенте) и Пароль (label «Пароль», `type="password"`, переключатель
   показать/скрыть). Каждое поле — видимая подпись, не только плейсхолдер.
   Фокус — кольцо `--color-ring`.
3. **Кнопка «Войти».** Primary, на всю ширину карточки; при отправке —
   состояние загрузки (disabled + спиннер), при неверных данных — inline-
   ошибка: карточка destructive «Неверный email или пароль» над формой.
4. **Продолжить как гость.** Под кнопкой — ссылка «Продолжить как гость»
   (возврат в чат без авторизации) и «Вернуться на главную».
5. **Примечание о ролях.** Под блоком — caption: «Вход не обязателен. Без
   входа доступны общие агрегированные данные.»
6. **Демо-доступ (опционально, для среды разработки).** Скрытый по
   умолчанию блок с кнопкой «Заполнить демо-учёткой» — подставляет учётки
   из [seed.md](seed.md) (demo_student / demo_teacher / demo_admin) без
   публикации паролей.

## Гостевой доступ

- **Сессия:** отдельная гостевая сессия без привязки к бизнес-ролям
  (applicant/student/teacher/admin). Роль в интерфейсе не показывается —
  бейдж «Гость» без ролевой маркировки.
- **Данные:** только минимальный публичный набор — агрегированные и
  обезличенные данные (например, направления подготовки, количество мест,
  статистика прошлых лет). Правила — в [roles.md](roles.md).
- **Интерфейс:** селектор ролей в чате отсутствует; гостевой баннер
  объясняет ограничение и предлагает войти.
- **Переход к авторизации:** после входа сессия переходит в
  авторизованную, бейдж и доступные данные обновляются, история чата
  сохраняется.

## Адаптивность и темы

- **Точки:** 375px (мобильный), 768px (планшет), 1024px (ноутбук),
  1440px (десктоп). Проверка в ландшафтной ориентации.
- **Мобильный чат:** шапка ужимается (лого + бейдж + иконка меню), лента и
  композер на всю ширину; клавиатура не перекрывает композер (учёт
  safe-area и scroll). Тач-цели ≥ 44px.
- **Тёмная тема:** полностью независимая палитра (см. токены), контраст
  проверяется отдельно от светлой. Переключатель — в шапке, сохраняется в
  настройках пользователя.
- **Сокращённое движение** и **динамический размер текста** поддерживаются
  без поломки раскладки.

## Что не входит в этот документ

- Реализация (стек, структура файлов, разметка) — отдельный этап.
- Страницы управления учётками для администратора — отдельный этап
  (в [roadmap.md](roadmap.md) учтено).
- Точные тексты ответов ассистента и формулировки ошибок могут уточняться
  на этапе реализации без изменения дизайн-системы.
