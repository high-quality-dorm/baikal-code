# Baikal

Безопасный text-to-SQL сервис для университетской базы данных PostgreSQL.

Baikal принимает вопрос на естественном языке, превращает его в SQL-запрос,
исполняет строго через единственный шлюз доступа и возвращает понятный ответ.
Система рассчитана на студентов, преподавателей, абитуриентов и администрацию
университета — каждый видит только те данные, которые ему положены.

## Как это работает

1. Пользователь задаёт вопрос по-русски (в веб-чате или через API).
2. LLM генерирует SQL — только read-only SELECT, с лимитом строк и учётом
   прав пользователя.
3. SQL исполняется через **единственный шлюз доступа** — пакет `db_mcp`:
   жёсткая валидация, ролевое маскирование схемы, Row-Level Security и аудит
   запросов.
4. Ответ пересказывается LLM на естественном языке и возвращается вместе
   с метаданными (SQL, время выполнения, число строк).

Детали устройства — в [architecture.md](architecture.md).

## Возможности

- **Роли и RLS (deny-by-default, set-based):** роль выводится из `student_id`/
  `staff_id` пользователя; студент видит только свои оценки, преподаватель —
  студентов своих групп, администрация — всё. Гость видит только общую
  информацию.
- **Защита персональных данных:** PII-поля студентов (имя/фамилия/отчество)
  доступны только тем, кому RLS открывает строку студента; гостю они недоступны.
- **Аудит:** каждый запрос фиксируется в `query_log` (кто, что, когда).
- **Конвейер `/api/v1/ask`:** вопрос → SQL → исполнение → ответ по-русски.
- **Веб-интерфейс:** лендинг, чат, вход; гостевой доступ без регистрации.

## Требования

- [uv](https://docs.astral.sh/uv/) — менеджер пакетов и окружений (Python 3.12)
- Docker + Docker Compose — для PostgreSQL
- Node.js ≥ 18 — для веб-интерфейса
- `openssl` — для генерации JWT-ключей (`make certs`)

## Быстрый старт

```bash
make sync                       # установить зависимости (uv sync --all-packages)
make certs                      # сгенерировать RSA-ключи для подписи JWT (RS256)
cp .env.example .env            # настроить подключение к БД и LLM
make db-up                      # поднять PostgreSQL в docker (схема, роли, RLS)
make seed                       # заполнить базу синтетикой
make run                        # запустить приложение (FastAPI на :8000)
```

После этого откройте веб-интерфейс (см. ниже) или обращайтесь к API напрямую.

## Первый вход

Хранилище учётных записей стартует пустым. Первого администратора создаёт
эндпоинт `POST /api/v1/auth/bootstrap-admin`:

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/auth/bootstrap-admin \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"secret"}'
```

Дальше админ управляет учётками через `POST /api/v1/auth/users`
(при создании указывает `student_id`/`staff_id` — связку с доменной сущностью,
через которую RLS вычисляет доступ):

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/auth/users \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <access_token>" \
  -d '{"email":"student@example.com","password":"secret","student_id":1}'
```

> Примечание: пакеты приложения (`app`/`db_mcp`) сейчас описывают старую модель
> доступа (роль строкой, `internal_id`) и будут перестроены под новую
> set-based модель (`student_id`/`staff_id`); база данных уже переведена на неё
> (см. [architecture.md](architecture.md)).

Вход по логину/паролю — `POST /api/v1/auth/login`, он возвращает
JWT access-токен (RS256), который используется для `/api/v1/ask`.

## Веб-интерфейс (frontend)

SPA на React + Vite. Дизайн — в [design.md](design.md).

```bash
cd frontend
npm install      # установить зависимости (первый раз)
npm run dev      # dev-сервер на :5173, /api проксируется на :8000
npm run build    # production-сборка в frontend/dist
```

В чате можно работать без входа (гостевой доступ — только общие агрегированные
данные). Когда бэкенд недоступен или у пользователя нет токена, чат отвечает
локальным mock-ассистентом (детерминированно, по данным сида).

## Команды

| Команда        | Что делает                                              |
| -------------- | ------------------------------------------------------- |
| `make sync`    | Установить зависимости (uv sync --all-packages)         |
| `make certs`   | Сгенерировать RSA-ключи для JWT (в `certs/`)            |
| `make run`     | Запустить приложение (FastAPI на :8000)                 |
| `make db-up`   | Поднять PostgreSQL в docker                             |
| `make db-down` | Остановить БД                                           |
| `make db-reset`| Пересоздать БД с нуля (схема + роли + RLS)              |
| `make seed`    | Заполнить базу синтетикой                               |
| `make format`  | Форматирование (ruff)                                   |
| `make check`   | Линт + type check + проверка документации (ruff, ty, check_docs.py) |
| `make docs-check` | Только проверка документации                         |
| `make test`    | Запустить тесты (pytest)                                |
